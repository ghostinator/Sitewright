# Network & privacy

The browser only talks to the app's own origin (no CDNs, fonts, analytics or third-party scripts). All outbound traffic is made **by the PHP server**, exclusively through `core/SafeHttpClient.php`.

| # | Destination | When | What is sent | Disable |
|---|---|---|---|---|
| 1 | **Websites you enter** (SEO/Competitor analysis, Image SEO page + its images, Sitemap crawl and its `robots.txt`) | Only when a logged-in user submits that form | `GET` requests for the URLs involved; User-Agent `Sitewright-SEO/1.0 (+SW_CONTACT)`; your server's IP address becomes visible to those sites | Restrict with `SW_FETCH_ALLOW_HOSTS`; or remove the feature by not granting accounts. Private/internal addresses are always refused. |
| 2 | **generativelanguage.googleapis.com** (Google Gemini) | Only if `SW_GEMINI_API_KEY` is set, when a user runs *Generate* or *Rewrite* | The prompt: your keyword (≤200 chars, control chars removed), content type, tone — or the text you asked to rewrite (≤5000 chars). The API key is sent in the `x-goog-api-key` **header**, never in the URL. Response bodies are not logged. | Leave the key empty |
| 3 | **nominatim.openstreetmap.org** (OpenStreetMap) | Only if `SW_ENABLE_GEOCODING=true` **and** a location is added without coordinates and no stored location has the same address; max 1 request/second | The address text (street, city, state, postal code, country) as the `q` parameter; identifying User-Agent | Leave `SW_ENABLE_GEOCODING` unset/false (default) or enter coordinates yourself |
| 4 | **Your connected WordPress sites** (`SiteSync`) | Every `sites.sync_minutes` (10) per connected site, and on "Sync now" | Signed `GET`/`POST` to `https://your-site/?rest_route=/sitewright/v1/...`: the redirect rules for that site. Received: the site's 404 paths and referrers (no IPs, no user agents), and, **only for each data type the site owner ticks in WordPress (Settings, Sitewright; all off by default)**: site title, tagline, language and time zone; the address, title and last-changed date of each public page and post (no text, authors or comments); the search title, description and noindex flag from Yoast or Rank Math; existing redirects from the Redirection or Rank Math plugin; the WooCommerce shop address; image counts; WordPress and PHP versions with counts of waiting updates. Never offered: users, e-mail addresses, customers, orders, page text, comments, plugin or theme names. Sitewright asks only for ticked types, refreshes them every `sites.remote_hours` (6), and deletes what it stored when a tick is removed or the site is removed. Everything received is treated as untrusted: markup removed, lengths and counts capped | Untick the type in WordPress, or remove the site on the Sites page |
| 4b | **Your own sites' public pages** (`SiteProfile`, the setup guide) | When a site is added, every `sites.profile_days` (7; 0 = off) per site, and on "Read the site again" | `GET` of the site's home page, `/robots.txt`, and (only if robots.txt lists none) `/sitemap.xml` and `/wp-sitemap.xml`, to that site's own host only; the same guarded client and User-Agent as a crawl. Nothing is sent that identifies you. Received: the title, description, language, platform, robots rules, and any business name, phone and address in the page's structured data. All of it is untrusted text: markup and control characters removed, lengths capped, wrong-shaped values dropped. Only items an administrator chose to use or typed are used elsewhere | Set `sites.profile_days` to 0 and do not press "Read the site again" |
| 4c | **Your own sites' HTTPS certificates** (`SiteExpiry`) | Every `sites.expiry_hours` (24) per https site, and when a site is added | A TLS connection to port 443 of the site's own host (the same address checks as every fetch; the connection goes to the checked address). Nothing is sent but the host name (TLS server name). The certificate is read: expiry date, issuer, names | Remove the site |
| 4d | **Domain registration dates** (`SiteExpiry`, RDAP) | Same schedule, and `sites.rdap_enabled` (on by default) | `GET https://data.iana.org/rdap/dns.json` (the list of registries, at most weekly) and `GET <registry RDAP address>/domain/<your site's domain name>`. The request to IANA carries no domain name (it only downloads the public list). The domain name of each site is sent to the registry that holds it, which is public registration data being asked about the owner's own domain. No page content, no secrets, no account data | Settings, *Look up domain expiry dates* off, or remove the site |
| 4e | **Let's Encrypt** (`Certificates`, `Acme`) | When a certificate is created, renewed (30 days before expiry) or re-made after switching between test and real | `GET`/signed `POST` to `acme-v02.api.letsencrypt.org` (real) or `acme-staging-v02.api.letsencrypt.org` (test). Sent: the domain names of the certificate, a certificate request (public key), the contact address from *Settings, Certificates* (optional), and an account key (generated here, kept encrypted). Received: the signed certificate | Delete the certificate; leave the page unused |
| 4f | **Your DNS host** (Cloudflare: `api.cloudflare.com`; Spaceship: `spaceship.dev`) | During issuing and *Test*, with the API token you entered | Cloudflare: look up the zone, add one TXT record `_acme-challenge.<name>`, delete it afterwards. Spaceship: the same through its DNS records API. Nothing else is read or changed. The token is stored encrypted and never sent anywhere but that provider | Delete the DNS account |
| 4g | **Your servers fetch certificates from Sitewright** (`CertPullController`) | Every few hours per server, started by that server | Sitewright sends the certificate chain and **private key** to a server that presents its own token (one token per server, optional list of allowed addresses, throttled, https only). Sitewright never connects to the servers | Delete the server in Sitewright: its token stops working at once |
| 5 | **Your mail server** (`mail.host`, e.g. Postal) | Password-reset / invitation e-mails and e-mail alerts | SMTP: recipient, subject, plain-text body. Not through the SSRF guard: it is operator configuration, usually private; TLS is verified | Leave `mail.host` empty |
| 6 | **Microsoft Teams Workflows webhook**, **api.telegram.org** | Alerts, when configured | Alert text (event name and a short description; never secrets, passwords or request bodies). The Telegram token is part of its URL and is never logged | Leave the settings empty |
| 8 | **www.googleapis.com/pagespeedonline** (Google PageSpeed Insights) | Only if an administrator turns on *Measure Core Web Vitals* under Settings, and only when someone presses *Measure Core Web Vitals* or a watched page has Web Vitals switched on (about once a week) | The address of the page being measured (public addresses only; private and internal ones are refused before anything is sent). Google then loads the page itself. The optional API key travels in a request header, never in the address | Leave *Measure Core Web Vitals* off (the default) |
| 7 | **accounts.google.com, oauth2.googleapis.com, www.googleapis.com** (Search Console) | Only after an administrator connects Google Search Console; then once a day and on "Sync now" | OAuth code exchange (with PKCE), token refresh, the read-only `searchAnalytics.query` for the chosen property. Received: query, date, clicks, impressions, CTR, position. The refresh token is stored encrypted | Disconnect on the Analytics page (also revokes the grant at Google) |

Nothing else: no update checks, telemetry, or phone-home. XML namespace URLs inside generated sitemaps and `https://schema.org` in JSON-LD are text, never fetched.

## Data stored

* Analysis history (URL, score, result JSON), generated content history, image and sitemap URLs, locations (name, address, phone, e-mail, coordinates), keyword metrics, redirect rules.
* **404 log**: URI, referer, user agent, IP address *as entered/imported by an administrator*. Entries older than `retention_days_404` (default 90 days) are purged on write and by `php bin/purge-404.php` (suitable for cron). Treat IP addresses as personal data under GDPR-style regimes; set retention accordingly.
* Accounts: username, e-mail, password hash. Sessions: server-side PHP sessions.
* Login throttling counters (hashed keys) in `rate_limits`.

## Outbound controls

* `SW_FETCH_ALLOW_HOSTS`, `SW_FETCH_BLOCK_HOSTS` — narrow where analysis/crawling may go (never bypasses the private-address block).
* `SW_FETCH_DEV_ALLOW_CIDRS` — **development only**; disables the private-address block for the listed ranges.
* Egress firewall rules at the host level remain the strongest control; the application guard is defence in depth.

## Privacy notice (what this application stores about people)

| Data | Whose | Where | Retention |
|---|---|---|---|
| Username, display name, password hash (bcrypt/argon via `password_hash`), optional TOTP secret and hashed recovery codes | Administrators | `users` table | Until the account is removed |
| Audit log: time, username, action, client IP | Administrators | `audit_log` table | `retention_days_audit` (default 365), purged by `php bin/purge-audit.php` |
| 404 log: URI, referer, user agent, IP | Site visitors, **as entered or imported by an administrator** (the app does not capture visitors itself) | `monitor_404` table | `retention_days_404` (default 90) |
| Session data | Administrators | PHP session files | Idle 30 min / absolute 8 h |
| DNS API tokens, ACME account key, certificate private keys and chains | You (the administrator) and Let's Encrypt | `dns_providers`, `acme_accounts`, `certificates` tables, **encrypted with `app_key`** | Until deleted; keep `app_key` safe and backed up separately (a restored database without it cannot decrypt them) |
| Certificate and domain expiry dates per site | Site owners (public information) | `site_expiry` table | Replaced on every check; deleted with the site |
| What a site's owner approved the plugin to share (pages, search titles, redirects, shop address, counts) | Site owners (their own public pages and settings; no personal data of visitors or customers) | `site_remote`, `site_pages`, `site_seo` tables | Replaced on every refresh; deleted when the owner withdraws the tick or the site is removed |
| Locations (business name, phone, address, email) | Businesses/people the administrator enters | `local_locations` table | Until deleted |
| Password-reset tokens (SHA-256 only), recovery-code hashes | Administrators | `password_resets`, `recovery_codes` | Reset links: 60 min (invitations 7 days), single use |
| Search-query data from Search Console (query, clicks, impressions, position) | Your site's visitors (aggregated by Google) | `analytics_keywords` | Until deleted; no visitor identifiers |
| Search Console query and page rows (last 28 days, replaced on every sync) | Your site's visitors (aggregated by Google) | `search_pages` | Replaced each sync; no visitor identifiers |
| Watchlist history, site audits (extracted facts about your own pages, no page bodies) and Core Web Vitals results | Your own sites | `watch_items`, `seo_analysis`, `audits`, `audit_pages`, `audit_issues`, `pagespeed_runs` | Scheduled analyses `watch.retention_days` (365); the newest `audit.keep` (10) audits per site |
| 404 paths and referrers pulled from connected sites | Site visitors (no IP/UA) | `404_monitor` | `retention_days_404` |

IP addresses and user agents are personal data under GDPR-style regimes. Name a controller, state the purpose (security monitoring, site maintenance), keep the retention values at the minimum you need, and publish this table (or your version of it) as your privacy notice. The application sets no tracking cookies and loads no third-party scripts; its only outbound destinations are listed above.
