# Sitewright

A small, self-hosted PHP + vanilla-JS toolkit for a few common on-page SEO tasks. The audit found no code from any commercial SEO plugin in this repository, and the app does not implement "all" features of any such product.

**Status: suitable for controlled local testing and staging. Read [Limitations](#what-it-does-and-does-not-do) and [Remaining risks](docs/remediation/REMEDIATION_REPORT.md) before exposing it to the internet.**

## What it does (and does not do)

| Area | What actually happens |
|---|---|
| **SEO Analysis / Competitor** | Fetches one URL from the server (through the guarded HTTP client) and runs heuristic on-page checks: title, meta description, H1, image alt text, links, viewport tag, HTTPS (final URL), JSON-LD presence, word count. Not Lighthouse, not Core Web Vitals, not Search Console. |
| **Image SEO** | Reads `<img>` tags (`src`, `data-src`, first `srcset` candidate) from a page's HTML, downloads up to 50 images (≤10 MB each) and reports alt text, byte size and pixel dimensions. JavaScript-injected images are not seen. Alt-text suggestion is **filename-based, not AI**. |
| **Sitemaps** | Crawls same-site HTML pages (hard cap 500, robots.txt `User-agent: *` honoured, 2-minute budget) and generates a plain URL sitemap XML. News/Video/Image sitemaps are **not** supported. |
| **Content AI** | With no key: fixed sentence **templates** (labelled as such). With a Gemini API key: text generated by Google Gemini; every result says which path produced it (`source`: `gemini` / `template_fallback` / `template`). `rewrite` styles `simplify`/`expand` need Gemini; otherwise only simple rule-based substitutions are offered. |
| **Keyword research** (API only) | Looks keywords up in **your own imported data**. There is no search-volume source. Generic suggestion phrases are returned separately and labelled `template`. |
| **Analytics** | Shows keyword metrics you add/import yourself through the API. **No Google Search Console / OAuth / SEMrush integration exists.** |
| **Local SEO** | Store business locations, generate LocalBusiness JSON-LD (API), radius search (API). Geocoding via OpenStreetMap is **off by default**. |
| **404 Log** | A log you fill manually or import. **It does not detect 404s on your website.** Retention purge after 90 days (configurable). |
| **Redirect Rules** | A rule manager with Apache/nginx/CSV export. **It does not perform redirects itself** (this app is not in front of your site). |

## Requirements

* PHP **8.1 or newer** (tested on 8.1, 8.3 and 8.4) with `pdo_mysql`, `curl`, `mbstring`, `dom`, `json` (`intl` recommended for IDN hosts)
* MariaDB 10.5+ (tested on 10.11 and 11.8) or MySQL 8 (generated columns and `SHA2()` are used; MySQL 8 is untested)
* Apache (mod_rewrite, mod_headers; `AllowOverride FileInfo` is enough: `.htaccess` uses no Options/Indexes/AuthConfig directives) or nginx + PHP-FPM
* HTTPS for anything beyond localhost

## Install (CLI)

```bash
git clone <repo> && cd sitewright
# Create a MariaDB database/user. Use a privileged account for this step only (see docs/DEPLOYMENT_GUIDE.md).
export SW_DB_PASS='…'                       # never put secrets on the command line
export SW_ADMIN_PASSWORD='at least 12 characters'
php bin/install.php --db-host=127.0.0.1 --db-name=sitewright --db-user=sw_admin \
                    --admin-user=admin --admin-email=you@example.com --create-db
```

The installer validates every input, applies the migrations, creates the first administrator (no default account exists), writes `config/config.php` (mode 0600) and a lock file; it refuses to run twice. There is no web installer.

Point the web server's **document root at `public/`** and set `SW_BASE_URL` and `SW_ALLOWED_HOSTS` (see below). Upgrade later with `php bin/migrate.php`.

Quick local try-out without Apache: `SW_DB_NAME=… SW_DB_USER=… SW_DB_PASS=… php -S 127.0.0.1:8080 -t public tests/router.php`.

## Configuration

`config/config.php` (git-ignored; template: `config/config.example.php`) and/or environment variables. Environment wins.

| Variable | Purpose |
|---|---|
| `SW_DB_HOST` `SW_DB_PORT` `SW_DB_NAME` `SW_DB_USER` `SW_DB_PASS` `SW_DB_PREFIX` | Database (runtime account needs only `SELECT, INSERT, UPDATE, DELETE`) |
| `SW_BASE_URL` | Public URL incl. sub-path, e.g. `https://seo.example.com` |
| `SW_ALLOWED_HOSTS` | Comma-separated hostnames accepted in the `Host` header (default: `localhost,127.0.0.1,[::1]`) — protects against DNS rebinding |
| `SW_GEMINI_API_KEY` / `SW_GEMINI_MODEL` | Optional Content AI (default model `gemini-3.6-flash`; models are retired regularly — check Google's list) |
| `SW_ENABLE_GEOCODING` | `true` sends location addresses to nominatim.openstreetmap.org (default `false`) |
| `SW_CONTACT` | URL/e-mail added to the User-Agent of outbound requests |
| `SW_FETCH_ALLOW_HOSTS` / `SW_FETCH_BLOCK_HOSTS` | **Outbound** host allow/block lists (separate from `SW_ALLOWED_HOSTS`; the IP safety checks always apply) |
| `SW_FETCH_DEV_ALLOW_CIDRS` | **Development only**: exempt ranges from the private-address block (e.g. to analyse a local test site) |
| `SW_CONFIG_FILE` | Path of the config file if it lives outside the repo (default `config/config.php`) |
| `SW_TRUSTED_PROXIES` | Comma-separated IPs/CIDRs of your reverse proxies; only then is `X-Forwarded-For` believed (never `/0`) |
| `SW_HSTS`, `SW_DEBUG` | HSTS header when served over HTTPS; verbose errors (never in production) |

Run `php bin/check-env.php` to verify the environment (CLI only).

## Security model

> Behind a reverse proxy: the proxy must preserve the `Host` header (the same-origin check uses it), and login throttling uses the connecting IP, so all users behind one proxy share a single throttle bucket. Trusted-proxy handling is not implemented.

* **Authentication**: session login against the `users` table (bcrypt/argon via `password_hash`). Single role — every account is an administrator. All API routes require a session except `GET /api/health` and `POST /api/auth/login`. Login is throttled (5 failures / 15 min per account, 30 / 15 min per IP). Cookies are `HttpOnly`, `SameSite=Lax`, `Secure` over HTTPS; idle timeout 30 min, absolute 8 h.
* **CSRF / CORS**: no CORS headers at all (same-origin only). State-changing requests need `Content-Type: application/json`, an `X-CSRF-Token` header, a same-origin `Origin`, and an allowed `Host`.
* **SSRF**: every outbound request goes through `core/SafeHttpClient.php` — http/https and ports 80/443 only, DNS resolved and every address checked (loopback, private, link-local/metadata, CGNAT, reserved, IPv4-mapped/NAT64/6to4), connection pinned to the checked address, redirects revalidated (max 5), 5 MB/10 MB size caps, timeouts, TLS verification on.
* **XSS**: the front end never parses server data as HTML (DOM nodes + `textContent`); CSP is `script-src 'self'; style-src 'self'` with no inline code.
* **Headers**: CSP, `X-Content-Type-Options`, `X-Frame-Options: DENY`, `Referrer-Policy`, `Permissions-Policy`, optional HSTS.
* Errors are logged server-side; clients get generic messages plus a request id.

## Network & privacy

See [docs/NETWORK_AND_PRIVACY.md](docs/NETWORK_AND_PRIVACY.md) for every outbound destination, what is sent, and how to disable it. ## Development & tests

```bash
tests/docker/run.sh 8.1          # php -l + 292 PHP tests on PHP 8.1 against a disposable MariaDB (Docker)
tests/docker/run.sh 8.3
(cd tests/js && npm install && npm test)   # jsdom XSS/renderer tests
tests/docker/smoke.sh up         # Apache root (:8081) + sub-path (:8082/seo) + fixture site, for browser smoke tests
```

Layout: `public/` (only web-exposed directory) · `core/` framework · `modules/` controllers · `config/` · `database/migrations/` · `bin/` CLI tools · `tests/` · `docs/`.
